# Подключение Claude Code к мосту

Мост отдаёт нативный Anthropic Messages API на `127.0.0.1:8765`, поэтому
официальный Claude Code работает с ним без патчей — достаточно двух переменных
окружения.

## 1. Запустить мост

```powershell
cd D:\CodeWorks\claude-web-api
.\scripts\setup.ps1     # только первый раз: portable Python, зависимости, Camoufox
.\scripts\start.ps1
```

При первом запуске откроется окно Camoufox — войдите в свой аккаунт
`claude.ai`. Сессия сохранится в `profile\`, дальше браузер работает headless.

Проверка, что мост живой:

```powershell
curl.exe http://127.0.0.1:8765/health/ready
```

## 2. Направить Claude Code на мост

```powershell
$env:ANTHROPIC_BASE_URL = "http://127.0.0.1:8765"
$env:ANTHROPIC_AUTH_TOKEN = "local-claude-web"
claude
```

Bash / WSL / macOS:

```bash
export ANTHROPIC_BASE_URL="http://127.0.0.1:8765"
export ANTHROPIC_AUTH_TOKEN="local-claude-web"
claude
```

Мост не проверяет токен — он слушает только петлевой интерфейс. Переменная
нужна лишь потому, что клиент отказывается стартовать без учётных данных.

Клиент не знает имени `claude-web` и предупреждает об этом. Предупреждение
безобидно: размер контекста он берёт по умолчанию (200k). Убрать его можно так:

```powershell
$env:CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT = "1"
```

Чтобы не выставлять переменные каждый раз, положите их в `~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8765",
    "ANTHROPIC_AUTH_TOKEN": "local-claude-web"
  }
}
```

## OpenClaude

Подключается теми же двумя переменными — патч из `integrations/openclaude/`
нужен только для старого OpenAI-пути. Модель придётся передать флагом: свою
переменную окружения OpenClaude под неё не читает.

```powershell
openclaude --model claude-web
```

Если раньше OpenClaude ходил через мост по OpenAI-пути, проверьте
`~/.openclaude/.openclaude-profile.json`: активный профиль перекрывает
`settings.json`, и старый профиль продолжит гнать запросы в
`/v1/chat/completions`.

## 3. Выбор модели

Модель выбирается в панели управления (`http://127.0.0.1:8765/control/`), а не
флагом клиента: мост переключает модель внутри web-сессии. Значение `--model`
передаётся как есть и разрешается против списка моделей, доступных аккаунту;
неизвестное имя не роняет запрос, но и не даёт модели, которой у аккаунта нет.

Список того, что реально доступно:

```powershell
curl.exe http://127.0.0.1:8765/v1/models
```

## Что работает

- Обычный диалог и потоковый вывод.
- Полный цикл инструментов: Claude возвращает `tool_use`, Claude Code выполняет
  Read/Edit/Bash у вас на машине, `tool_result` уходит обратно и продолжает тот
  же ход в браузере.
- Панель управления показывает текущий запрос, историю, метрики и профили.

## Что не работает и почему

| Ограничение | Причина |
|---|---|
| Картинки и документы в запросе | Браузерный ход переносит только текст и вызовы инструментов; такие блоки возвращают `400`, а не теряются молча |
| `thinking`-блоки в ответе | Мост не может подписать summary так, чтобы клиент мог его переиграть, поэтому thinking не выдаётся как блок контента (в панели он виден) |
| `max_tokens` | Валидируется, но не ограничивает: web-сессия отдаёт уже готовый ответ |
| Серверные инструменты (`web_search`, `code_execution`) | У браузерного хода нет их эквивалента — определения отклоняются |
| `/v1/messages/count_tokens` | Возвращает **оценку** по длине текста: у claude.ai нет доступного токенизатора. Клиент использует её для прикидки контекста |
| Точный `usage` | Приходит только если upstream его прислал; иначе честные нули, без выдуманных чисел |

## Если что-то пошло не так

**`connection refused`** — мост не запущен либо занят другой порт. Проверьте
`.\scripts\start.ps1` и переменную `PORT`.

**Запрос висит, потом `503`** — браузерная сессия не готова: возможно, нужен
повторный вход. Откройте панель, вкладка **Профили**.

**`409` про identity или project prompt** — Project Instructions аккаунта
изменили извне. Мост намеренно останавливается, вместо того чтобы переписать
чужую правку; разберите конфликт в панели.

**После `Ctrl+C` первый следующий запрос иногда отвечает без инструментов** —
Claude в новом чате отвечает как обычный собеседник («не вижу такого файла»).
Мост при этом здоров: повторите запрос, второй уже работает нормально.

Сам обрыв больше не ломает мост: брошенный вызов инструмента отпускается, а
браузер не перезапускается — раньше пять прерываний подряд открывали
предохранитель перезапусков и клали мост целиком.

**`429`** — упёрлись в лимит аккаунта. Если добавлено несколько профилей, мост
переключится сам; иначе придётся подождать.

Подробности запроса — в панели управления и в `/api/control/telemetry`.

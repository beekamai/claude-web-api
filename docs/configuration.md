# Настройка

Всё управляемое живёт в панели `http://127.0.0.1:8765/control/` и сохраняется
в `control_config.json` (образец — `control_config.example.json`).

**Где лежат данные.** Код и состояние разделены: конфиг, браузерные профили
(`profile\`, `profiles\`) и журнал лежат **вне** папки репозитория — в
`%LOCALAPPDATA%\claude-web-api` (Linux: `~/.local/share/claude-web-api`,
macOS: `~/Library/Application Support/claude-web-api`). Папку с кодом можно
удалить, заменить свежим архивом или переместить — вход в аккаунты и
настройки останутся. Другое место задаётся переменной `CLAUDE_WEB_API_DATA`.
Состояние, которое старые версии держали рядом с кодом, переносится при первом
запуске автоматически; профиль, занятый открытым браузером, переезжает при
следующем старте.

## Профили и авторизация

Добавление аккаунта:

1. Панель → **Профили** → добавить профиль.
2. Выбрать `Claude Web`, задать локальное имя.
3. Запустить вход — откроется отдельный **видимый** Camoufox.
4. Войти в claude.ai и дождаться проверки в панели.
5. Сервер подтвердит авторизацию, прочитает разрешённый список моделей и
   создаст (или переиспользует) Claude Project `OpenClaude IDE` для аккаунта.
6. Активировать готовый профиль.

Новый профиль создаётся в `profiles\<profile-id>\`. `control_config.json` хранит
настройки, маскированную идентичность и солёный fingerprint — по нему
распознаётся повторно добавленный аккаунт, — но не cookies и не сырые UUID.
Каталоги `profile\` и `profiles\` содержат чувствительное состояние браузера:
их нельзя публиковать и передавать.

Окно добавления закрывается кнопкой отмены; забытое закроется само через
`CLAUDE_ENROLLMENT_TTL` секунд (по умолчанию 900).

**Ротация при лимите.** При account usage limit профиль помечается временно
ограниченным, и мост переключается только на готовые, включённые и
неограниченные профили. Автоповтор разрешён лишь до появления видимого вывода
или начала tool path: неоднозначный ход после вывода не повторяется, чтобы не
выполнить `Bash`, `Write` и прочее дважды. Если подходящих профилей нет — `429`.

**Прокси профиля.** Панель → **Профили** → кнопка **Прокси** в строке. Каждый
профиль может выходить через свой socks5 или http(s)-адрес, с логином и
паролем; строку провайдера можно вставить целиком:
`socks5://логин:пароль@host:1080` — логин и пароль будут разобраны из неё.

* **Проверить выход** соединяется через прокси на самом деле (SOCKS5-хендшейк
  или `CONNECT`) и показывает внешний адрес и задержку; ошибка называет
  причину — отказ по паролю, недоступный хост, отсутствие ответа.
* **Сохранить и применить** перезапускает браузер активного профиля: без
  перезапуска он продолжил бы ходить со старого адреса. Если Claude в этот
  момент ждёт `tool_result`, панель ответит `409` и настройка останется
  сохранённой, но неприменённой — повторите после завершения хода.
* SOCKS5 с логином и паролем Firefox сам не умеет (Playwright отвечает
  «Browser does not support socks5 proxy authentication»), поэтому мост
  поднимает на `127.0.0.1` локальный ретранслятор без пароля, а с настоящим
  прокси авторизуется сам. Браузер видит только loopback-адрес; пароль из
  процесса не выходит. http(s)-прокси с паролем браузер принимает напрямую.
* Вместе с прокси включается `geoip`: Camoufox берёт часовой пояс, локаль и
  WebRTC-адрес от точки выхода, а не от этой машины.
* Пароль хранится в `control_config.json` рядом с профилем и наружу не
  отдаётся — панель видит только признак «пароль сохранён». Пустое поле пароля
  означает «оставить сохранённый».

Вход в аккаунт открывается через тот же прокси, что и рабочая сессия, поэтому
аккаунт не окажется зарегистрированным с одного адреса и используемым с другого.

**Grok** (`grok_web`) экспериментален и fail-closed: xAI отклоняет и Camoufox, и
управляемый Playwright Chrome, поэтому профиль остаётся `provider_blocked` либо
`protocol_unverified`, а completion для него выключен.

## Модели

Список читается из model selector авторизованного аккаунта; недоступные,
disabled, legacy и deprecated варианты выбираемыми не считаются. Выбор хранится
отдельно для каждого профиля и проверяется против его фактического списка.

- `claude-web` или `auto` — модель, выбранная для активного профиля, либо
  автоматический выбор claude.ai;
- конкретный model ID — только если он доступен аккаунту;
- `GET /v1/models` — список известных доступных моделей.

Общий bootstrap-каталог моделей используется только для отображения: до
получения свежего account-scoped selector строка помечается непроверенной и не
может быть выбрана. Причина `upgrade_required` показывается в панели вместе с
требуемым тарифом.

## Privacy: обычные и temporary chats

- `keep` — обычный Project chat, видимый в истории аккаунта.
- `ephemeral` — чат остаётся привязанным к проверенному IDE Project (поэтому
  Project Instructions сохраняют системный приоритет), но `is_temporary: true`
  не даёт рабочим ходам засорять историю чатов claude.ai.

Это не приватный режим браузера: persistent-профиль и авторизация сохраняются.
Дополнительно панель не дублирует тексты новых temporary-запросов в
`telemetry.sqlite3`. Локальная сессия самого клиента продолжает храниться у вас
на машине. Серверную политику хранения данных определяет Anthropic.

## Режимы общения

Поверх неизменяемого IDE/tool-контракта:

- `default` — без дополнительной роли;
- `programmer` — инженерный IDE-режим;
- `custom` — пользовательская инструкция.

`actor` и `mature` — независимые переключатели, а не взаимоисключающие персоны;
их можно включить поверх любого режима. Первый усиливает непрерывность
художественного образа, второй задаёт прямой взрослый регистр, но сам по себе
не добавляет тему, персонажа или сцену — тему задаёт реплика пользователя, а
допустимость ответа определяет провайдер. `mature` не является обходом правил:
он не отменяет политики Anthropic, защиту несовершеннолетних и требования
согласия.

Сохранение custom-персоны в панели сразу активирует режим `custom`. Персона
передаётся как обычная пользовательская настройка текущего хода, а не как
псевдосистемная инструкция, и переживает восстановление браузера, смену чата и
ротацию профиля. Переключение на `default` явно отменяет сохранённую карточку.

Исходный текст хранится без изменений; перед отправкой узкий компилятор
переформулирует только конфликтные требования вроде «реальный человек» или
«не упоминай ИИ» как свойства персонажа внутри сцены. Панель показывает
исходник и итоговый вариант вместе со списком преобразований.

Мост не может прочитать или заменить скрытый provider-owned prompt claude.ai.
Claude вправе проигнорировать карточку или выйти из роли — мост в любом случае
возвращает настоящий ответ, без подмены отказа заглушкой и без переписывания
результата.

## Переменные окружения

```text
PORT=8765                        порт API и панели
CLAUDE_HEADLESS=1                основной браузер без окна
CLAUDE_DEBUG_REQUESTS=1          подробный лог запросов
CLAUDE_DEBUG_BROWSER=1           отладка браузерного слоя
CLAUDE_DEBUG_SSE=1               отладка потока событий claude.ai

CLAUDE_PROFILE_DIRS=<пути>       legacy bootstrap существующих профилей (; на Windows)
CLAUDE_PROJECT_ID=<uuid>         явный project uuid основного профиля
CLAUDE_START_URL=<url>           явный стартовый URL claude.ai
CLAUDE_ENROLLMENT_TTL=900        таймаут окна добавления профиля

CLAUDE_WATCHDOG_INTERVAL=10      период проверки живости браузера
CLAUDE_WATCHDOG_PROBE_TIMEOUT=4  таймаут одной проверки
CLAUDE_WATCHDOG_STALL_TIMEOUT=90 после какого простоя ход считается зависшим
CLAUDE_BROWSER_START_TIMEOUT=330 таймаут запуска браузера
CLAUDE_BROWSER_CLOSE_TIMEOUT=10  таймаут закрытия
CLAUDE_READY_TIMEOUT=<сек>       ожидание готовности сессии
CLAUDE_RESTART_WINDOW=600        окно подсчёта перезапусков
CLAUDE_RESTART_LIMIT=5           сколько перезапусков в окне допустимо
CLAUDE_TOOL_RESULT_TIMEOUT=<сек> ожидание результата инструмента
CLAUDE_TOOL_RESULT_POST_TIMEOUT=20 таймаут отправки результата
CLAUDE_HUMANIZE_SECONDS=0.25     задержка ввода

OPENCLAUDE_TELEMETRY_DB=<путь>   файл журнала запросов
```

## Журнал запросов

Живой журнал и метрики — в панели и в `GET /api/control/telemetry`. Хранилище —
SQLite в `.runtime/telemetry.sqlite3`; глубина хранения и лимит записей
настраиваются в панели. Пароли, токены, cookies, UUID аккаунта и содержимое
инструментов в журнал не попадают: всё, что покидает процесс, проходит через
`sanitize.py`.
